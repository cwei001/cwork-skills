# BP 三层分析框架

## 一、分析模型概述

BP 健康度分析采用**三层分析模型**，从基础结构到执行落地逐层深入：

```
Layer 1: 基础健康度检查（数据结构层）
    ↓
Layer 2: 方向一致性检查（业务语义层）
    ↓
Layer 3: 执行真实性检查（汇报内容层）
```

---

## 二、Layer 1：基础健康度检查

**数据来源**：`/bp/task/v2/getSimpleTree`（任务树接口）

### 检查维度

| 维度 | 判断逻辑 | 评分权重 |
|------|---------|---------|
| **结构完整性** | 目标→成果→举措层级是否完整<br>❌ 空节点、断层 | 20% |
| **时间合理性** | 举措截止 ≤ 成果截止 ≤ 目标截止<br>❌ 时间倒挂、重叠 | 20% |
| **状态一致性** | 子任务进行中但父任务草稿？<br>子任务关闭但父任务进行中？ | 15% |
| **责任明确性** | 每个节点都有 undertaker？<br>❌ 责任真空、多人负责模糊 | 20% |
| **对齐完整性** | 有上级承接？有下级分解？ | 25% |

### 问题识别

| 问题类型 | 症状 | 严重程度 |
|---------|------|---------|
| **空节点** | 有目标无成果，或成果无举措 | 🔴 高 |
| **时间倒挂** | 子任务截止晚于父任务 | 🔴 高 |
| **状态冲突** | 父子状态不一致 | 🟡 中 |
| **责任真空** | 节点无负责人 | 🔴 高 |
| **无对齐** | 目标无上级承接或无下级分解 | 🟡 中 |

---

## 三、Layer 2：方向一致性检查

**数据来源**：`/bp/task/v2/getGoalAndKeyResult`（目标详情接口）

### 检查维度

| 维度 | 判断逻辑 | 标准 |
|------|---------|------|
| **方向一致性** | 举措语义是否支撑成果？<br>成果语义是否支撑目标？ | 名称关键词关联度 |
| **衡量标准清晰度** | measureStandard 是否满足 SMART 原则 | ✅ 具体、可量化、可验证、有时限<br>❌ 模糊描述如"提升""加强" |
| **粒度合理性** | 举措周期是否适中（1周-3月） | ❌ 太大（超过3月）或太小（几天） |
| **资源冲突** | 同一人在同一时期多个高优先级任务 | 标记潜在资源冲突 |

### 衡量标准质量判断

| 等级 | 特征 | 示例 |
|------|------|------|
| ✅ 优秀 | 量化+时限+可验证 | "AI产品收入占比达到40%，2026年Q4完成" |
| 🟡 合格 | 可验证但无量化 | "完成BP系统核心功能交付并通过验收" |
| ❌ 不合格 | 模糊描述 | "提升AI产品竞争力"、"加强团队建设" |

## 四、Layer 3：执行真实性检查

**数据来源**：`/bp/task/relation/pageAllReports`（汇报记录接口）

### 分析维度

| 维度 | 分析逻辑 |
|------|---------|
| **计划匹配度** | 汇报时间与计划节点是否对应？ |
| **进展一致性** | 汇报描述的进展 vs 状态是否一致？ |
| **风险识别** | 汇报中提到的延期、阻塞、风险 |
| **方向漂移** | 实际工作与目标方向是否偏离？ |
| **完成质量** | 汇报的深度、具体程度 |

### 汇报质量评估

| 等级 | 特征 |
|------|------|
| ✅ 优秀 | 有具体数据、完成百分比、明确下一步计划 |
| 🟡 合格 | 有进展描述，但缺乏量化 |
| ❌ 差 | 模糊描述如"正常推进中"、"按计划进行" |

---

## 五、评分标准

### 健康度评分等级

| 分数 | 等级 | 建议 |
|------|------|------|
| 90-100 | 优秀 | 保持，可作为标杆 |
| 70-89 | 良好 | 小范围优化 |
| 50-69 | 待改进 | 需要调整结构或内容 |
| <50 | 不合格 | 需要重构BP |

## 六、分析触发场景

| 场景 | 分析深度 | 所需数据 |
|------|---------|---------|
| **快速健康检查** | Layer 1 | 任务树 |
| **深度执行分析** | Layer 1+2+3 | 任务树 + 目标详情 + 汇报 |
| **季度/月度复盘** | Layer 1+2+3 | 特定时间段汇报 + 目标进展 |

## 八、技术实现要点

### 时间冲突检测
```python
def check_time_conflict(parent, children):
    parent_end = parse_date(parent.get('planEndDate'))
    for child in children:
        child_end = parse_date(child.get('planEndDate'))
        if child_end > parent_end:
            return True, f"子任务截止晚于父任务"
```

### 衡量标准质量判断
```python
def is_good_kr(kr):
    measure = kr.get('measureStandard', '')
    # 好的KR：有量化数字 + 有时间
    has_number = any(c.isdigit() for c in measure)
    has_time = any(w in measure for w in ['Q1', 'Q2', 'Q3', 'Q4', '月', '周'])
    return has_number and has_time
```
